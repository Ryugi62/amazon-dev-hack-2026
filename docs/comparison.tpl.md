# What NextOne does that existing options do not

Checked 2026-10-16 (host model row measured {{llm_replan.date}}). "Verified" means I read the page text; "reported" means a third-party review.

| Existing option | What it does for a running-late day | What it does not do | Source |
|---|---|---|---|
| Alexa+ reminders and task list (Amazon) | One task list for reminders and to-dos. Snooze: "Snooze reminder for 20 minutes", "Remind me again in an hour". Verified. | Snooze moves that one reminder. Nothing re-plans the other items or protects fixed events from overlap. | https://digprjsurvey.amazon.com/csad/help/node/T30e4eImkYHXKiYbvr |
| Alexa+ follow-up reminders (Amazon) | "Alexa sends you reminder notifications every hour or day until you confirm that you've completed the task." Verified. | The confirmation is the user's word. A spoken "done" always counts. NextOne does not record done without a photo, file, link or third_party signal. | same page |
| Alexa reminders set by voice or app (Amazon) | Time and recurrence based reminders, assignable to a household member. Verified. | Fire at a set time; no day-level plan, no "what is next" answer with previews. | https://digprjsurvey.amazon.com/csad/help/node/GDDXYWQUKGGWG79Y |
| Host LLM default capability (Alexa+ model that calls the add-on) | I found no page that says what the Alexa+ model does here, so I measured a stand-in: {{llm_replan.model_count}} hosted Gemini models (free tier, run {{llm_replan.date}}) were told in plain language "I'm N minutes late, re-plan the rest of my day, do not move fixed events" on seeded synthetic days. Of {{llm_replan.measured}} answers scored, {{llm_replan.overlap_runs}} left overlapping time ({{llm_replan.overlap_percent}}%), {{llm_replan.fixed_blocks_moved}} fixed events were moved and {{llm_replan.missing_blocks}} blocks were lost. {{llm_replan.unmeasured}} of {{llm_replan.attempted}} calls failed (daily limits, overload) and are not counted. Details and per-model table: README, section "Versus the host model alone". | A prompt is a request, not a guarantee: one of the models measured did leave overlaps. NextOne's server refuses a plan with an overlap or a moved fixed event on every call, and also keeps state across sessions and checks proof for done. These Gemini models are not the Alexa+ model, so this is a stand-in measurement, not a claim about Alexa+. | Prompt: `scripts/llm-replan-prompt.txt`; script `scripts/llm-baseline.js`; raw answers' scores: `docs/llm-baseline/` |
| Motion (calendar and task planner) | Reported to reschedule the rest of the day automatically when you fall behind, shifting lower-priority work. Reported, not verified by me. | Not an Alexa+ add-on; reported pricing from $19 per month; no proof requirement for done. | https://www.morgen.so/blog-posts/motion-review |

**What only NextOne has:** inside the Alexa+ conversation, a re-plan with a proof you can check (0 overlapping minutes, fixed events untouched) and a done that needs evidence. The numbers behind that line are in `docs/metrics.json`.

**Honest limit:** snooze plus follow-up already covers a late single task. On the days measured, most Gemini models also produced a clean re-plan when the rules were in the prompt ({{llm_replan.clean_runs}} of {{llm_replan.measured}} answers had no overlap, no moved fixed event and no lost block), so NextOne's claim is not that a model cannot re-plan a day. It is that the rule is enforced by the server instead of left to the model's answer, that state survives sessions, and that done needs proof.
